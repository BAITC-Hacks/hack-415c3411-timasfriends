# Bastamat в браузере

Клиент собирается Unity 6000.3.7f1 в `Builds/WebGL`. Собственная страница загрузки занимает всё окно браузера; дополнительный сайт для локальной демонстрации не нужен.

23 сентября 2026 сборка Bastamat с браузерным текстовым мостом завершилась успешно: **0 ошибок**, размер файлов около **64 МБ** без сжатия. Единственное предупреждение сообщает, что Editor-мост Pipeline отключён в Player из-за отсутствия RuntimePipelineConfig; работа приложения от этого моста не зависит. Локальная страница, логотип, шрифт и браузерный модуль вернули HTTP 200, API через тот же сервер ответил `status: ok`. Полный пользовательский сценарий именно в браузере и публичное HTTPS-размещение ещё не проверены.

## Сборка

1. Установить модуль **WebGL Build Support** для Unity 6000.3.7f1.
2. Дождаться завершения импорта/компиляции, выйти из Play mode.
3. Выбрать **WebGL** как активную платформу в Build Profiles и дождаться переключения.
4. Выполнить меню **QuestBridge → Build Web Preview**.

Editor-метод `QuestBridge.Editor.QuestBridgeWebBuild.BuildPreview()` использует только сцену `Assets/QuestBridge/QuestBridge.unity`, шаблон `PROJECT:QuestBridge` и пишет результат в `Builds/WebGL`. `QueuePreview()` ставит ту же сборку в очередь следующего Editor update, чтобы вызов автоматизации успел вернуть управление. Состояние и результат сохраняются в `Temp/questbridge-web-build.json`: `building`, `succeeded` или `failed`.

Первая сборка без компрессии: серверу не нужны специальные заголовки сжатия. Это ускоряет настройку демонстрации, но увеличивает скачивание. Исключения, явно брошенные кодом, сохраняются: клиент обрабатывает ошибки сети и данных через `try/catch`. Скрипт сохраняет изменённые Player Settings. Выходные папки `Builds/` и `Temp/` игнорируются Git.

## Локальный запуск

Из корня репозитория запустить backend по [его инструкции](../backend/README.md). В отдельном терминале:

```powershell
backend/.venv/Scripts/python.exe scripts/serve_web.py
```

Также подойдёт системный Python 3.10+: `python scripts/serve_web.py`. Дополнительные пакеты этому скрипту не нужны.

Открыть **http://localhost:8080/**. Сервер отдаёт готовую сборку, правильно обозначает `.wasm` и проксирует `/api/*` и `/health` на `http://127.0.0.1:8000`. Поэтому браузер работает с одним origin и дополнительная настройка CORS для этого пути не нужна. Backend запускается отдельно. Без него приложение сможет показать демонстрационный каталог, но серверные действия будут недоступны.

```powershell
# Другая папка сборки или адрес backend
python scripts/serve_web.py --directory Builds/WebGL --port 8080 --backend http://127.0.0.1:8000
```

## Адрес сервера во время запуска

Шаблон после загрузки вызывает `QuestBridgeApp.ConfigureServer(string)` на объекте сцены с именем `QuestBridge`.

| Адрес страницы | Режим |
| --- | --- |
| `http://localhost:8080/` | API на том же origin: `http://localhost:8080/api/...` |
| `http://localhost:8080/?showcase=1` | Тот же API; дополнительно видна кнопка симуляции рейтинга «Демо» |
| `http://localhost:8080/?offline=1` | Явное автономное демо; пустой адрес сервера |
| `http://localhost:8080/?api=https%3A%2F%2Fapi.example.com` | Отдельный backend `https://api.example.com` |

`api` — базовый адрес **без `/api` в конце**, поскольку клиент дописывает `/api/catalog`, `/api/chat` и остальные маршруты. Перезагрузите страницу для смены параметров. Адрес API не является ключом. Ключ OpenAI остаётся в окружении backend.

Для отдельного домена API необходимо включить origin сайта в `CORS_ORIGINS` backend. Для HTTPS-страницы backend также должен использовать HTTPS. Параметр `api` с HTTP на HTTPS-странице отклоняется до запуска.

## Публикация

Два варианта размещения:

1. **Один домен:** отдать содержимое `Builds/WebGL`, а `/api/*` и `/health` направить reverse proxy на backend. Шаблон автоматически использует origin сайта.
2. **Статический хостинг + отдельный API:** загрузить содержимое сборки и использовать `?api=https%3A%2F%2Fадрес-сервера` с корректным CORS. Укажите готовую ссылку с параметром в README.

Один GitHub-репозиторий или GitHub Pages не запускает Python backend. Публичный сайт с `127.0.0.1:8000` обращается к компьютеру посетителя. Для удалённого доступа нужен опубликованный backend или общий домен с reverse proxy. `scripts/serve_web.py` — сервер локального предпросмотра, без собственного TLS.

Страница уже полноэкранная по размеру окна. Если нужен внешний сайт, можно встроить URL сборки:

```html
<iframe src="/bastamat/" title="Bastamat"
        allow="fullscreen; autoplay" allowfullscreen
        style="position:fixed;inset:0;width:100%;height:100%;border:0"></iframe>
```

Когда сборка лежит в подпапке, обращения к API всё равно идут к корню origin. Размеры браузерного окна и звук после первого взаимодействия необходимо проверить в реальной сборке: Editor не подтверждает поведение браузера.

## Перед сдачей

- Открыть URL в новом окне браузера; дождаться загрузки без ошибок Console/Network.
- Выполнить полный сценарий бизнеса и команды; обновить страницу и убедиться, что опубликованные серверные данные сохранились.
- Проверить ввод, выделение и вставку текста, прокрутку, изменение размера окна и звук после клика.
- При клике по полю WebGL использует DOM textarea поверх Unity; Ctrl/Cmd+C/V/X/A работают средствами браузера. Текст переписки и полных карточек выделяется по клику. При клике по кнопке последнее изменение сначала передаётся в Unity, затем отправляется запрос. Проверить длинный текст и IME; автоматическое браузерное прохождение не выполнялось.
- Проверить явный автономный режим `?offline=1`.
- Для публичной ссылки повторить сценарий со второго устройства; проверить HTTPS и доступность API.
- В README различать исходники, локальную инструкцию и фактически опубликованную ссылку.

Сборку и эти ручные проверки выполняют отдельно; создание скриптов не означает, что они уже пройдены.

Основа интеграции: [официальная документация Unity 6.3 по шаблонам и взаимодействию с Unity instance](https://docs.unity.com/en-us/engine/6000.3/manual/platform-specific/webgl/building-distribution/templates/web-templates-build-configuration).
