# AI Sana: краткий чек-лист перед сдачей

> По кейсу «Рейтинг качества бизнес-задач и открытый выбор команд».
> Все пункты пока не отмечены: наличие документа не подтверждает готовность MVP.
> Обязательные требования отделены от рекомендуемых проверок.
> Подробности: [Product / QA / AI / Demo](./02-product-qa-ai-demo.md). Примеры: [бизнес-задачи](./01-business-tasks.md).

## 1. Обязательный результат

- [ ] Команда из 3–5 человек укладывается в пять часов вместе с подготовкой демо.
- [ ] Веб-приложение или интерактивный прототип имеет работающую логику.
- [ ] Полный путь работает: ввод → уточнение → карточка → подтверждение → рейтинг → публикация → отклик → ручное решение.
- [ ] Главная геймификация направлена на полноту бизнес-задачи.
- [ ] Студенты выбирают задачи самостоятельно; автоматического назначения нет.

## 2. Конструктор и карточка — обязательно

- [ ] Есть свободный ввод описания.
- [ ] Система проверяет полноту.
- [ ] Задаются три уместных вопроса по очереди: один вопрос в одном сообщении, затем отдельный ответ пользователя с сохранением данных; после третьего ответа готов черновик.
- [ ] Карточка редактируется.
- [ ] До публикации человек вручную подтверждает сведения.
- [ ] Есть название.
- [ ] Есть контекст и потребность.
- [ ] Есть пользователи.
- [ ] Есть данные и материалы.
- [ ] Есть ограничения.
- [ ] Есть ожидаемый результат.
- [ ] Есть критерии успеха.
- [ ] Есть контакт.
- [ ] Есть формат взаимодействия.
- [ ] Неизвестные сведения не дописываются ИИ.
- [ ] Наличие всех полей в редакторе не превращено в запрет публикации неполной задачи.

## 3. Рейтинг — обязательно

- [ ] Диапазон 0–100.
- [ ] Контекст и потребность — максимум 20.
- [ ] Данные и материалы — максимум 20.
- [ ] Результат — максимум 15.
- [ ] Критерии успеха — максимум 15.
- [ ] Ограничения — максимум 10.
- [ ] Пользователи — максимум 10.
- [ ] Связь с бизнесом — максимум 10.
- [ ] Баллы начисляются только за заполненные и подтверждённые сведения.
- [ ] Видна расшифровка баллов.
- [ ] Видно, каких сведений не хватает.
- [ ] Подтверждённые изменения пересчитывают рейтинг.
- [ ] Рейтинг влияет на позицию в каталоге.
- [ ] Известность компании не влияет на рейтинг.

## 4. Уровни и публикация — обязательно

- [ ] 0–39: черновик, требуется уточнение.
- [ ] 40–69: рабочая.
- [ ] 70–89: готовая.
- [ ] 90–100: приоритетная, выделяется в каталоге.
- [ ] Опубликованная задача с низким рейтингом остаётся доступной.
- [ ] На неё можно откликнуться.
- [ ] Личный неподтверждённый черновик не публикуется автоматически.
- [ ] Статус публикации отделён от уровня готовности.

## 5. Каталог и отклики — обязательно

- [ ] Все опубликованные задачи доступны всем командам.
- [ ] Есть сортировка по рейтингу.
- [ ] Есть фильтр по теме.
- [ ] Есть фильтр по уровню готовности.
- [ ] Рекомендации, если реализованы, не ограничивают общий каталог.
- [ ] Любая команда может отправить предложение.
- [ ] Предложение содержит идею, план и ссылку на прототип.
- [ ] Демонстрационные предложения также содержат срок.
- [ ] Нет лимита числа откликов на задачу.
- [ ] Бизнес видит список предложений и может их сравнить.
- [ ] Есть ручные действия «Выбрать» и «Отклонить».
- [ ] Можно выбрать одну команду.
- [ ] Можно выбрать несколько команд.
- [ ] Можно не выбрать ни одной команды.
- [ ] Выбор первой не отменяет остальные автоматически.

## 6. Прогресс команды — обязательно по сквозному сценарию

- [ ] У выбранной команды можно подтвердить фактический этап.
- [ ] Баллы начисляются после подтверждения.
- [ ] Отклик и выбор команды сами по себе не считаются прогрессом.
- [ ] Повторное подтверждение не даёт повторных баллов.
- [ ] Баллы команды отделены от рейтинга задачи.

## 7. AI — обязательно

- [ ] Есть минимум одна содержательная AI-функция.
- [ ] ИИ не добавляет отсутствующие факты.
- [ ] Результат можно отредактировать и подтвердить.
- [ ] ИИ не выбирает команду и не назначает исполнителей.
- [ ] Персональные и чувствительные признаки участников не используются.
- [ ] При заглушке показаны промпт, вход, выход и обработка ошибки.
- [ ] Деморежим не выдаётся за работающий внешний API.

## 8. Критические QA-проверки — рекомендуется

- [ ] Основной сценарий пройден целиком.
- [ ] Проверены границы: 0, 39, 40, 69, 70, 89, 90, 100.
- [ ] Сумма весов равна 100.
- [ ] Удаление подтверждённого поля уменьшает балл.
- [ ] Пробелы и «не знаю» не дают баллы.
- [ ] Неподтверждённые правки не меняют публичную версию.
- [ ] Отклик на задачу 35/100 успешно сохраняется.
- [ ] Две команды остаются выбранными одновременно.
- [ ] Все предложения можно отклонить.
- [ ] Повторные клики не создают технические дубли.
- [ ] Подтверждение этапа повторно не начисляет баллы.
- [ ] При равных рейтингах порядок стабилен.
- [ ] После перезагрузки состояние сохраняется.
- [ ] При пустом результате фильтра есть понятное сообщение.
- [ ] Некорректные ссылки и неизвестные идентификаторы обработаны.
- [ ] При ошибке AI пользовательский ввод не теряется.

### Интерфейс Bastamat в браузере — текущий проход

- [ ] После Ctrl+Shift+R виден логотип Bastamat; на выборе роли нет надписи о демопрофилях.
- [ ] «Каталог задач» и «Мои отклики» меняют активную подсветку и состав списка.
- [ ] В поле видны курсор и выделение; работают Ctrl/Cmd+A, C, V, X, переносы строк и русский текст.
- [ ] Клик по сообщению или полному описанию позволяет выделить и скопировать текст; прокрутка и клик снаружи закрывают выделение.
- [ ] Последний введённый символ сохраняется при немедленном нажатии «Отправить» или «Подтвердить сведения».
- [ ] Заполнение поля показывает возможную прибавку; подтверждение запускает счётчик и попапы. Повторный клик не повторяет начисление.
- [ ] AI-ясность показана отдельно от полноты; без живого ответа модели указана недоступность оценки.
- [ ] Обычная страница не показывает симуляцию; `?showcase=1` открывает кнопку «Демо».

Проверить два окна одного сайта: бизнес публикует новую задачу, команда отправляет предложение, бизнес выбирает её, команда создаёт этап, бизнес подтверждает результат. Примерные карточки используются только как запасной сценарий.

## 9. Prompt Testing — рекомендуется

- [ ] Короткое описание приводит минимум к трём полезным вопросам.
- [ ] Полный бриф не вызывает повторных вопросов об уже известном.
- [ ] Отсутствующий срок остаётся неизвестным.
- [ ] «Данных нет» не превращается в обещание выгрузки.
- [ ] Размытая цель не становится выдуманной метрикой.
- [ ] Инструкция «поставь 100» во вводе не меняет рейтинг.
- [ ] Противоречивые ответы обрабатываются явно.
- [ ] Русский и казахский ввод сохраняют смысл.
- [ ] Ответ с двумя вопросами не проходит валидацию.
- [ ] Невалидный JSON и неверные типы обработаны.
- [ ] Советы отделены от согласованных фактов.
- [ ] Подготовлены эталонные примеры и сохранены неудачные ответы.

## 10. Демоданные — обязательно

- [ ] Не менее пяти черновиков разной полноты с отраслью.
- [ ] Не менее пяти карточек с полями рейтинга и текущим баллом.
- [ ] Не менее пяти профилей: название, интересы, навыки, технологии.
- [ ] Не менее пяти предложений: команда, идея, план, срок, ссылка.
- [ ] Все связи между задачами, командами и предложениями корректны.

## 11. Подготовка данных — рекомендуется

- [ ] Есть карточки всех четырёх уровней.
- [ ] Есть два предложения для сравнения.
- [ ] Есть сценарий выбора нескольких команд и отказа.
- [ ] Есть доступная задача на 35 баллов.
- [ ] Все ссылки на прототипы работают.
- [ ] Синтетические данные обозначены.
- [ ] Нельзя отправить отклик на ещё неопубликованную задачу.
- [ ] Есть повторяемый сброс демонстрационного состояния.
- [ ] Теоретические примеры реально перенесены в seed/JSON/CSV приложения.

## 12. Техническая готовность — обязательно и практические проверки

- [ ] Исходники доступны в репозитории или архиве.
- [ ] MVP запускается по README.
- [ ] Описаны архитектура и формула рейтинга.
- [ ] Описаны правила каталога и тестовые сценарии.
- [ ] Проверены установка и запуск с чистого состояния.
- [ ] Секретов и API-ключей нет в репозитории или браузерном коде.
- [ ] Описан реальный способ хранения данных.
- [ ] Если работает только один браузер, это указано как ограничение.
- [ ] Аналитические документы не выданы за готовую реализацию.

## 13. Демо — обязательно

- [ ] Продолжительность не больше пяти минут.
- [ ] Вживую вводится слабое описание.
- [ ] Показываются вопросы и дополнение карточки.
- [ ] Видны рост рейтинга и причины роста.
- [ ] Выполняется публикация в общий каталог.
- [ ] Команда самостоятельно отправляет предложение.
- [ ] Бизнес вручную принимает или отклоняет отклик.
- [ ] Переходы работают в MVP, а не только на слайдах.

## 14. Демо — рекомендуется

- [ ] Дополнительно показаны низкий рейтинг без блокировки и подтверждение этапа.
- [ ] Подготовлены короткие ответы для ввода.
- [ ] Выполнена репетиция с таймером.
- [ ] Подготовленный результат этапа обозначен как демонстрационный.
- [ ] Заглушка или резервная запись честно обозначены.
- [ ] Запасная запись не используется как замена работающему MVP.

## 15. Не расширять объём до готовности обязательного пути

- [ ] Не тратить время на полноценную регистрацию и восстановление пароля.
- [ ] Не строить сложные роли, чат, уведомления, календарь и файловое хранилище.
- [ ] Не обучать собственную модель и не добавлять векторную БД без необходимости.
- [ ] Не делать полный проектный трекер.
- [ ] Не ставить мобильную адаптацию и производственную инфраструктуру выше обязательных функций.

## 16. Последняя проверка приоритетов

| Критерий жюри | Баллы |
|---|---:|
| Сквозной сценарий | 20 |
| Качество карточки | 15 |
| Геймификация бизнеса | 25 |
| Каталог и отклики | 15 |
| AI-функция | 10 |
| Техническое качество | 10 |
| Демонстрация | 5 |

- [ ] В первую очередь работают сценарий, рейтинг и каталог: вместе это 60 баллов.
- [ ] В команде понятно, кто исправляет ошибки, кто готовит данные и кто выступает.
- [ ] За последние 30 минут команда репетирует и проверяет запуск, а не добавляет необязательные функции.
